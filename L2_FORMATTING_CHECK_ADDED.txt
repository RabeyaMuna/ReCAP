WHAT WAS ADDED:
----------------

Safety check after manually editing Python files:
  "Check for issues: ruff check <edited_file>"
  "If issues found, fix with: ruff check --fix <edited_file> && ruff format <edited_file>"

WHEN IT APPLIES:
----------------
✅ After manual code changes to *.py files (tests, src, type stubs, scripts)
✅ When editing Python files directly (changing imports, types, logic, etc.)
✅ Any manual modification that might introduce formatting/linting issues

WHEN IT DOES NOT APPLY:
------------------------
❌ When using automated formatters (black, isort, autopep8, ruff)
❌ Automated tools already handle formatting - no need to re-check

WHY THIS WAS NEEDED:
--------------------
Problem: Manual code changes can introduce:
  - Line length violations (> 88/100 chars)
  - Import sorting issues
  - Spacing/indentation problems
  - Unused imports
  - Missing type hints
  - etc.

Impact: These cause NEW CI failures, even if the original fix was correct!

Example from Instance 94 (aider):
  - Manual changes added 23 functions
  - Likely introduced formatting issues
  - CI failed on formatting, not the original error
  - Result: 82KB patch that failed bidirectional eval

UPDATED PATTERNS:
-----------------

PATTERN A: Config + Code fix
  Step 1: CONFIG - Open <config_file> and modify <section>
  Step 2: CODE - Open <source_file> and change <code>
  Step 3: Check formatting: ruff check <file> (if errors, run: ruff check --fix && ruff format)
  Step 4: Verify: <verification_cmd>

PATTERN B: Automated fix (formatting tool)
  Step 1: Install <tool>: <install_command>
  Step 2: Run automated fix: <fix_command>
  Step 3: Verify: <verification_cmd>
  NOTE: No Ruff check needed - automated formatter handles it

PATTERN C: Manual fix only
  Step 1: Open <file> at line <line_number>
  Step 2: Change <old_code> to <new_code>
  Step 3: Check formatting: ruff check <file> (if errors, run: ruff check --fix && ruff format)
  Step 4: Verify: <verification_cmd>
